## Trigger and changes

A reviewer reported that the member entry did not allow an invitation email to be entered. The previous demo accepted only a public username/password; its profile form displayed an input-like locked invitation address beside an editable contact address. The access choices and meaning of the fields were insufficiently clear.

- `/access` provides a single entry with explicit requirements for the no-login operational sandbox, sample email onboarding, demo administrator and live email/OTP account.
- `/demo` accepts an active sample invitation email scoped to this browser's six-hour workspace. It starts with member@example.org and supports invitations created by that same demo administrator. A one-click demo administrator desk and original test credentials remain available.
- The member profile shows the original invitation address as a reference. Contact email and requested designation remain editable. Only an authorised administrator confirms the approved institutional designation; software permissions stay separate.
- `/review-guide` explains the complete journeys and current access requirements. Public navigation uses Portal access; live sign-in points reviewers back to the sandbox choices.
- Author proof approval displays exact licence terms and records an explicit checkbox consent to the text/version. Missing or changed terms fail closed; changed live terms require reapproval before publication.
- Approved sample member details can pass from the operational sandbox to the welcome editor. It remains an export-only fictional package; provider publication is disabled.
